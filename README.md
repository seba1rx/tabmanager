# TabManager

**Package name:** `seba1rx/tabmanager`

TabManager provides **per-tab session isolation** for PHP applications.
It ensures each browser tab maintains its own independent session state, preventing shared session data between tabs — useful for admin dashboards, multi-step forms, or any multi-tab workflow.

---

## Features

- Isolates PHP session data per browser tab
- Lightweight JS client handles UUID assignment automatically
- Duplicate-tab detection: opening a tab via "Duplicate" generates a fresh UUID instead of inheriting the original's
- Periodic heartbeat keeps `last_active` accurate on the server while the tab is visible
- Tab ID sent as HTTP header (`X-TabManager-TabId`) on every AJAX request — cookies are shared across tabs and used only as fallback
- Built-in debug interface (JSON and HTML)
- No dependencies — pure PHP + vanilla JS

## How It Works

Each browser tab receives a unique UUIDv4 generated by the JS client and stored in `sessionStorage` (per-tab, survives reloads). On every AJAX request, the UUID is sent as the `X-TabManager-TabId` header. The PHP backend reads this header to isolate `$_SESSION` data per tab.

**Why header instead of cookie?** Cookies are shared across all open tabs for the same domain. If Tab 2 sets `TABMANAGER_TABID=uuid2`, Tab 1's cookie immediately becomes `uuid2` as well. The header is sent per-request with the correct per-tab UUID from `sessionStorage`.

**Duplicate-tab detection:** when a browser duplicates a tab it copies `sessionStorage`, so the new tab would inherit the same UUID. On init the JS client uses the `BroadcastChannel` API to ask whether any other running tab already owns that UUID. If so, a fresh UUID is generated before the tab is registered with the server. `TabManagerClient.init()` is therefore **async** — consumer code must await `TabManagerClient.ready` before using the tab ID.

**Heartbeat:** while a tab is visible the JS client POSTs to the heartbeat endpoint every 30 s, updating `last_active` on the server. The heartbeat pauses automatically when the browser hides or freezes the tab (Page Visibility API) and resumes — with an immediate beat — when the tab becomes visible again. This keeps server-side tab state accurate for lifecycle management and garbage collection.

## Usage

### 1. Include the autoloader

```php
require_once __DIR__ . '/vendor/autoload.php';
```

The bootstrap file is registered in Composer's `files` autoload and runs automatically, registering the internal endpoints.

### 2. Include the JS client

```html
<script src="/seba1rx_tabmanagerclient.js"></script>
```

This assigns a UUID to the current tab (resolving duplicates via `BroadcastChannel`), sets the `TABMANAGER_TABID` cookie as fallback, registers the tab with the backend, and starts the heartbeat.

`TabManagerClient.init()` is async. Await `TabManagerClient.ready` in your own scripts before using the tab ID:

```js
document.addEventListener('DOMContentLoaded', async () => {
    await TabManagerClient.ready;
    // TabManagerClient.tab.id is now confirmed and unique
});
```

### 3. Send the tab header on every AJAX request

```js
fetch('/your-endpoint', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        ...TabManagerClient.getHeaders()   // adds X-TabManager-TabId
    },
    body: JSON.stringify(payload),
});
```

### 4. Use the PHP API

```php
use Seba1rx\TabManager\TabManager;

$tabManager = new TabManager();

$tabManager->set('user_role', 'admin');
echo $tabManager->get('user_role'); // admin

print_r($tabManager->debug());
```

> `TabManager::set()` and `get()` resolve the tab ID from the `X-TabManager-TabId` header automatically — no need to pass the UUID manually.

## HTTP Endpoints

Registered automatically on every `require 'vendor/autoload.php'`:

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/tabmanager/new-tab` | Index a new tab in session |
| `POST` | `/tabmanager/heartbeat` | Update `last_active` for a tab (sent every 30 s by JS client) |
| `POST` | `/tabmanager/tab-close` | Mark tab as inactive |
| `GET` | `/tabmanager/debug_js` | Session dump as JSON (debug only) |
| `GET` | `/tabmanager/debug_html` | Session dump as HTML table (debug only) |
| `POST` | `/tabmanager/debug/delete-tab` | Delete a tab session (debug only) |

Debug endpoints are restricted to `127.0.0.1` / `::1` unless `define('TABMANAGER_DEBUG', true)` is set.

---

## Class Reference

| Method | Description |
|--------|-------------|
| `indexNewTab(string $tabId)` | Registers a new tab in session (idempotent) |
| `touchTab(string $tabId)` | Updates `last_active` and sets `is_active = true`; creates the tab if missing. Called by the heartbeat endpoint. |
| `set(string $key, mixed $value)` | Stores a value in the current tab's session |
| `get(string $key, mixed $default = null)` | Retrieves a value from the current tab's session |
| `destroyTabSession(string $tabId)` | Deletes all session data for a tab |
| `markInactiveTab(string $tabId)` | Marks tab as inactive (on `beforeunload`) |
| `debug(): array` | Returns a summary of all tab sessions |
| `uuid_v4(): string` | Generates a UUIDv4 (utility for consumers) |
| `is_valid_uuid(string $uuid, bool $onlyV4)` | Validates UUID format (utility for consumers) |

## JS Client Configuration

Set these globals **before** loading the script:

| Variable | Default | Description |
|----------|---------|-------------|
| `window.TABMANAGER_DEBUG` | `false` | Enables verbose console logging |
| `window.TABMANAGER_HEARTBEAT_URL` | `/tabmanager/heartbeat` | Heartbeat endpoint. Override when `/tabmanager/*` routes are unavailable (e.g. `php -S` without a router). |
| `window.TABMANAGER_HEARTBEAT_INTERVAL` | `30000` | Heartbeat interval in milliseconds |

```html
<script>
    window.TABMANAGER_HEARTBEAT_URL = '/api/tabmanager/heartbeat'; // custom route
    window.TABMANAGER_HEARTBEAT_INTERVAL = 15000; // 15 s
</script>
<script src="/seba1rx_tabmanagerclient.js"></script>
```

## Session Data Structure

```php
$_SESSION['tabmanager']['tabs'] = [
    '<uuid>' => [
        'data'        => [],           // key-value store for this tab
        'is_active'   => true,
        'last_active' => 1234567890,   // unix timestamp
    ],
];
```

## Security Notes

- Each tab UUID is random and conforms to RFC 4122 (v4).
- Tab IDs are sent as HTTP headers — not guessable from shared cookie state.
- Debug endpoints are localhost-only by default.
- All data is stored in `$_SESSION` — no external storage required.
